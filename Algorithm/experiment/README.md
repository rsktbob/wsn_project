# 分散式路由研究原型 v1

建議論文題目：**基於鄰居資訊與剩餘能量之無線感測器網路分散式路由決策研究**。

研究問題：節點只交換一跳鄰居資訊時，依剩餘能量調整路由成本，是否能降低中繼節點的耗能集中，延長固定感測需求下的服務時間？這是待驗證的假說，尚不是論文創新或改善效果的證明。

## 本版範圍

每個感測器自行選下一跳，基地台只公告自己可達。位置固定、基地台位置已知；預設所有節點感測等級固定為 5，每節點每 slot 產生專案既有的 generated_load。沒有搜尋編碼、QEA、感測開關最佳化或中央路由解碼器。`SensorEncoding.py` 完全未修改。

程式放在專案既有大寫 `Algorithm/experiment/`，不另外建立大小寫不同的 algorithm 目錄。這是獨立的訊息協定模擬實驗，不註冊為具有 fitness-evaluation budget 的 GA/QEA 演算法；這裡的 `--max-slots` 是服務時間上限，並非 10000 次候選解評估預算。

- `distributed_routing.py`：不可變的鄰居公告、局部觀察、選路政策與訊息模擬器。
- `run_distributed_routing.py`：地圖載入、逐 slot 重建路由、能量扣除及 CSV/JSON 輸出。
- `test_distributed_routing.py`：決策及協定不變量測試。

## 節點知道什麼

`LocalRoutingPolicy.choose(LocalObservation)` 沒有 Problem 或全網陣列的參照，只取得自己的 id、到 BS 距離、扣除本輪控制及感測成本後的能量、電路成本，以及各候選鄰居的一份公告。公告包含 id、到 BS 距離、剩餘能量、是否可達 BS、累積路徑指標與跳數。鏈路放大器成本由自身至該鄰居距離計算。

模擬器擁有拓樸是為了傳遞訊息和核算結果，不代表決策政策可讀全網。累積指標來自逐跳公告；它不是完整路徑或全域 fitness。

## 一個 slot 的流程

1. 鄰居探索假設：已知無線範圍內鄰居及距離，以 HELLO 交換當輪狀態。預設通訊範圍 30，這是**新實驗參數**，不是既有 Problem 的隱含參數。
2. 候選下一跳必須在通訊範圍內、符合原有鏈路遮罩，並且 rank 嚴格小於自己（sensor rank = 到 BS 距離，BS rank = -1，容許同位置 sensor 直連 BS）。原遮罩只限制鏈路長度不超過自己直達 BS 的長度，不等同於此新規則。
3. BS 先公告可達。每節點等待其所有較低 rank 候選鄰居公告後，用局部政策選下一跳，再公告自己的結果；無路徑也會公告不可達。每個同步 wave 只讀取先前 wave 的公告。
4. 決策完成後，觀察器還原路徑並累積真正的自產及轉送流量；資料與感測能耗使用既有 EnergyService，額外加上控制訊息耗能。
5. 整個固定需求 slot 可完成才扣除能量並計入 completed_slots，下一 slot 用新能量重新公告與選路。

無迴圈理由：每條選定邊滿足 rank(parent) < rank(node)，有限節點上不可能沿嚴格遞減 rank 回到起點。有限的 rank DAG 也讓公告程序至多經 N 個 sensor waves 結束。**無迴圈不保證有路可走**：嚴格距離限制會排除先繞遠再接近 BS 的路徑；BS 的特殊 root rank 處理與 BS 同位置的感測器。此版不支援移動、訊息遺失或過期公告。

## 三個策略

令 E_i 為節點 i 扣除本輪控制與感測成本後的能量；t_ij 為傳送一單位資料的電路加放大器成本，r_j 為接收電路成本（BS 不計能量），C_j 是鄰居公告的累積指標。

| 政策 | 節點 i 對候選 j 的評分，選最小者 |
| --- | --- |
| energy_balanced | t_ij / E_i + r_j / E_j + C_j |
| min_energy | t_ij + r_j + C_j |
| min_hop | 鄰居跳數 + 1 |

BS 的 C=0、能量無限；同分依鏈路傳送成本、節點 id 決定，結果可重現。每個策略用自己的評分生成 C。這是逐單位資料的啟發式，**沒有預知後續鄰居的轉送負載**，因此可能多個節點同時選同一中繼而過載。程式不宣稱容量保證，也不使用全域修復隱藏這類失敗。後續可研究逐跳流量保留/拒絕協定及負載公告，而非直接提供免費全網資訊。

## 通訊及能量假設

- 理想可靠、同步、無碰撞的鄰居單播；一次 HELLO 和一次路由狀態公告，每份預設 128 bits（可調整）。沒有 ACK、重傳、MAC idle listening 的成本。
- 對每一對實體鄰居的兩個方向各送兩份訊息：sensor 傳送扣 bits × (電路成本 + 放大器成本)，接收扣 bits × 電路成本。BS 能量不受限，但其訊息有計數，sensor 收取也耗能。
- 控制鏈路可雙向，資料路由另外受 rank/原遮罩限制。無效候選也可能收取公告，這部分計入成本。
- 當輪控制成本先保留再選路；若控制成本已超過可用能量，記 control_energy_shortfall。這是理想時槽模型的需求成本，不是在失敗時仍真的完成所有控制傳送。
- 每個 slot 都重建路由；未研究較長維護週期。初始發現鄰居的掃描、位置信息取得成本未建模。
- 固定所有節點都必須服務，不容許失效後關閉冗餘感測器。停止指標是本策略首個無法完整服務的 slot，不是最佳可能網路壽命。
- 失敗嘗試的 trace 能耗是診斷估計，未計入 paid_control_energy/messages；到上限標記 truncated=true，不當作真實失效。
- 最後一輪的全網覆蓋、能量檢查是離線評估；節點沒有收到這些數據作為學習回饋。

## 執行

在 `codes/2027WSN`：

```bash
python Algorithm/experiment/test_distributed_routing.py
python Algorithm/experiment/run_distributed_routing.py \
  --maps maps/maps_100100100.json --radio-range 30 --control-bits 128 \
  --level 5 --max-slots 2000 --output /tmp/distributed_routing_v1
```

可加 `--map MAP01` 單圖；`--policies energy_balanced` 單策略。預設三種策略各跑六圖。政策是確定性的，固定地圖無需用五個不同 seed 假裝成五個獨立樣本。輸出 config.json、summary.csv、每個 map/policy 的逐 slot trace（包含每個節點下一跳）。

## 論文實驗規劃

先比較以上三種分散式策略的 completed_slots、每 slot 能耗、最大中繼負載、公告 waves、控制訊息數、斷線/能量失敗原因，再擴充地圖和節點密度，改變通訊範圍與控制封包大小，加入無控制成本消融，檢查結果是否只是參數效果。能量平衡效果需要看每節點耗能分布，不能只由政策名稱推論。

若之後比較 Ring-SETS，需先統一感測需求、合法鏈路、控制成本及停止條件；目前 Ring-SETS 同時最佳化感測排程，不能把兩邊壽命直接視為同一問題的演算法勝負。量子啟發式/學習式節點政策應在此協定驗證後另加，與相同觀察、動作和通訊預算的傳統政策比較。

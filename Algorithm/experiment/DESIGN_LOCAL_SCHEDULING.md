# 分散式感測排程與路由：無訓練原型

建議題目：**考量覆蓋責任與轉送負載之無線感測器網路分散式感測排程與路由協調**。

研究目標：不用中央 SA-SETS 排程、不訓練模型，由每個節點選感測等級與下一跳，在維持目標覆蓋及基地台可達性的條件下延長 lifetime。此為理想控制通道下的局部決策模擬原型，尚不是已完成 MAC 與分散式終止偵測的部署協定。

## 本版已實作

### 1. 每個節點的局部觀察

`SchedulingView` 只含自己的 id、能量、初始能量、當前等級、自己的各等級感測成本與可覆蓋目標集合、自己的資料傳輸估計，以及**收到承諾訊息**後得知的目標覆蓋狀態。不含其他節點的能量表、全網 coverage table、全網 fitness 或 SA-SETS 解。

模擬器負責把自己的資料投影到每個 view。目標位置/id、重疊覆蓋鄰居、同儕的最大候選等級數/宣告大小，以及當輪醒著的鄰居名單，視為已知探索資訊；這些資訊的取得成本尚未建模。

### 2. 節點自行提出等級

每輪建立排程從候選等級 0 開始（原服務時槽不在此初始化期間執行），對比自己目前等級高的每個合法等級 l 計算：

`score = 新增尚未被承諾的目標數 × (預留控制能量後的剩餘能量 / 初始能量) / 新增感測與自產資料耗能`

第一次啟用包含自產資料傳輸估計；已啟用後只增加感測成本。估計資料成本採直達 BS 的自身 TX 成本，不估計未知轉送負載，因此可能排除實際上可透過多跳運作的低能量節點。

節點可保持關閉，也可逐步提高等級，最多進行自身合法正等級數次升級。這一輪不做降級或刪除已承諾責任，避免不斷來回變更。

### 3. 局部覆蓋責任承諾

每個節點依 score 設定反比優先計時，score 高者先到期。同分用 id。模擬器用事件排序執行這個理想競爭，不用全域 fitness 比較候選解。每次成功宣告後相關節點重算自己的候選。

到期節點宣告新負責的目標，傳給所有具最大範圍覆蓋重疊的參與節點，取得 ACK 後才處理下一件承諾。其他節點把這些目標從自己的「尚待負責」集合中移除。因所有可能共同負責某目標的參與節點都收到宣告，序列化、可靠資訊下不會同時把同一目標當成新責任。

這裡的責任唯一不代表物理覆蓋一定沒有重疊；某等級仍可能順帶覆蓋其他已承諾目標。排程成立後仍使用原 CoverageService 檢查全網是否覆蓋，該結果只供觀察器判定，未回饋節點政策或中央修復。

### 4. 控制能量保留與睡眠

每個節點利用自己的重疊鄰居數、最大合法升級次數、宣告長度，保留最壞情況的 claim/ACK 能耗上界。若預留後連一個正等級和自身資料估計都無法支付，該節點不參與這轮協調並保持睡眠，不要求它繼續收取所有宣告。

控制宣告長度為 64-bit header + 每個新目標 16 bits，ACK 為 64 bits。每個參與鄰居分別單播，分別計入發送放大器/電路和接收電路成本。實際排程控制能量必須不超過預留上界，程式有驗證。控制成本消融組仍保留完全相同的參與/能量預留規則，只把實際控制扣款設為零；同一能量狀態下兩組的排程決策相同，後續能量軌跡則會不同。

重疊覆蓋鄰居不一定符合原有資料候選鏈路。v1/v2 明確假設這些節點可以經**可靠直接控制單播**協調，使用實際幾何距離計價；不是隱含把多跳轉送當免費。若研究固定通訊半徑、封包遺失或多跳控制，此假設需另行替換。

### 5. 自行選路與服務

暫定感測等級交給本目錄 `ReservedRouting`，由每個啟用節點詢問已接入鄰居的剩餘容量與加入流量後預估可服務時槽數，自己選下一跳並逐跳預留流量。未接入的節點不會被選作 parent，避免迴圈。不讀 SA-SETS 的 levels、next_hops 或染色體。

資料轉送、感測耗能、覆蓋要求與 LifeCheck 沿用既有模型。安裝階段控制能量一次扣除，成功後維持該配置服務至不能再維持一個 slot，才建立下一個排程。不是每 slot 全網重建。

整份候選配置在排程及選路完成、可服務後才計入 lifetime。**目前尚未實作個別啟用申請的 route-before-commit、失敗責任撤回及候補接手**：若排程覆蓋不足、路由或含控制成本的能量不合格，就明確記為 infeasible_solution，沒有偷偷調用中央搜尋補救。失敗建構的訊息需求留在 trace，但未列入已支付控制能量。這是接下來最直接的改良點，而不是宣稱已達完整協定。

## 保證與限制

- 理想序列化、可靠控制與完整重疊鄰居資訊下，已承諾目標不被後續動作主動撤銷。
- 路由只接到已連 BS 的節點，因此無迴圈；不保證任意拓樸都能建立可行配置。
- 排程動作單調提高有限等級，最多 sum(K_i−1) 次提交後結束。
- 不保證最小感測成本、最大 lifetime 或每次都能找到已存在的可行解。
- 控制發現、醒睡名單、時鐘同步、MAC 碰撞/重傳、控制期間耗時/服務中斷未建模。
- 實作以全域事件排序近似理想局部優先計時，尚未實作有延遲的多節點並行競爭。
- 完全移除 SA-SETS 最佳化呼叫；政策不需訓練。使用既有 Problem/EnergyService 作環境不是中央控制器。

## 驗證與檔案

`local_scheduling.py`：局部排程政策及路由組合。
`run_local_schedule.py`：單圖控制成本消融與 lifetime runner。
`test_local_scheduling.py`：局部觀察、責任唯一、覆蓋、關閉節點、重現性測試。

執行（codes/2027WSN）：

```bash
PYTHONDONTWRITEBYTECODE=1 python -B Algorithm/experiment/test_local_scheduling.py
python -B Algorithm/experiment/run_local_schedule.py --map MAP01 --output results/local_schedule_v3
```

輸出及 NumPy/Numba 相關實驗快取均限定本目錄；不修改 SensorEncoding 或外部演算法。每次 runner 保存外部 .py/.md/.json 的前後雜湊稽核。

先檢查單圖、單 seed 的流程正確性，不用大量超參數試驗追逐單張圖成績。對照 SA-SETS 的單圖 seed 7 lifetime 1062；不能直接對照既有六圖五 seed 平均 1000.47 後宣稱比例。

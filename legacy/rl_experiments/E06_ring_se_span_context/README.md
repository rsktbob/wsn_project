# E06_ring_se_span_context

- 日期：2026-10-19
- 狀態：**seed 0 完成**（2026-10-19）
- 基底演算法：`ring_se`（Ring_SE 原版，SensorEncoding，n8 h4 w8 μ0.4，EN 更新）
- 設計圖：`design.svg`（輸入、網路、監督式／RL 訓練）

## 1. 目的

直接在**原版 ring_se** 上做監督式學習和強化學習，兩者用**同一個輸入、同一個網路**，只差訓練方式。

原版的候選範圍長度不固定（1–50 顆）、20% 會跨到相鄰段，所以 E04／E05 那種「固定 8 段 × 13 顆」的 slot 輸入不能用。
E03 的 DeepSets 只看範圍內的 sensor，看不到範圍旁邊和路由上的上下游。E06 改成：**全網 100 顆 sensor 先一起編碼（有前後文），
候選範圍只是一個遮罩**，從編碼後的 sensor 裡挑出範圍內的做池化。範圍多長、在哪裡、有沒有跨段都不影響網路結構。

要回答：

1. 全網前後文編碼能不能贏 E03（只看範圍內的 DeepSets +2.9%、瓶頸規則 +4.2%）？
2. 監督式、RL 從零、監督式暖啟動再接 RL，哪個最好？能拿到作弊版天花板（+7.5%）的多少？
3. 看後續回合（γ = 0.5）有沒有比只看眼前（γ = 0）好？

## 2. 問題設定（所有方法相同）

- **決策單位**：每回合每組 searcher-good 交易（8 × 8 = 64 次／回合；預算 1000 約 8 回合）。
- **動作**：4 個預抽候選選 1。每組交易先在 4 段各用原版 80/20 規則抽一個範圍（同 E03），網路選一個；
  均勻隨機選就等於原版 ring_se 的分布。交換、突變（只在選到的範圍內）、EN 更新都同 Ring_SE。
- **一個 episode**：一段最佳化，預算 1000。
- **環境**：fitness v3、SensorEncoding；訓練圖 `maps/maps_100100100_train.json`（沿用 E01 的訓練快照，190 張訓練、10 張驗證）；測試 MAP01–06。

## 3. 輸入（所有方法共用，`env.py`）

| 部分 | 形狀 | 內容 |
| --- | --- | --- |
| sensor token | 100 × 25 | **全網每顆 sensor**：searcher 解碼 10 ‖ good 解碼 10 ‖ E/E0、離 BS 距離 ‖ 差異旗標 3（欄位同 E03） |
| 路由父節點 | 2 × 100 | S、G 解碼後每顆 sensor 的父節點編號（BS 或沒開記 −1），給注意力偏置用 |
| 候選遮罩 | 4 × 100 | 第 c 個候選範圍內的 sensor 為 1 |
| 候選特徵 | 4 × 10 | 位置 4（起點/N、終點/N、長度/N、是否跨段）‖ 範圍外影響 4（同 E03）‖ 瓶頸分數 S、G 各 1（範圍內有效差異 sensor 的緊迫度總和） |
| 全域 | 10 | 同 E03 |

- sensor 順序是 ring-major（由內到外的距離環、環內依角度），和 ring_se 的段相同。
- token、候選特徵、全域做 z-score 標準化，統計量用隨機策略跑 40 段最佳化算一次（`results/data/norm.npz`）。
- 回合資料分兩層存：每個解（8 searcher＋8 goods）每回合只解碼、存一次；64 組交易的 token 由網路在 GPU 上組合。

## 4. 網路（監督式與 RL 相同，`model.py`）

```
sensor token (100×25) ─ φ 25→64→64 ─┐
                                   ├─ 2 層 Transformer（d64、4 頭、FF 128、pre-LN）
                                   │   注意力偏置 = 環上距離 |i−j| 分桶的可學偏置
                                   │              + 「j 是 i 在 S／G 的父節點或子節點」各一個可學偏置（每層、每頭）
                                   ▼
                        h_i（100×64，有前後文）
  候選 c：遮罩池化 平均 ‖ 最大 ‖ 總和÷50 (192) ‖ 候選特徵 10 → 202→128→64 → 候選 token u_c
  全域 10 → 64→64 → 全域 token g
  [g, u_1..u_4] → 1 層 Transformer（不加候選編號，對候選順序等變）
  Dueling：V = MLP(g') 64→64→1；A_c = 共用 MLP(u_c') 64→64→1；Q_c = V + A_c − mean(A)
```

- 輸出 **4 個 Q 值**（監督式也輸出 Q，之後才能直接接 RL）；選 Q 最大。154,170 參數；消融（sensor Transformer 0 層）86,978 參數。
- 設計理由：
  - 長度不固定 → 用遮罩池化，不用 slot；
  - 範圍外影響（路由上下游、旁邊的 sensor）→ 讓全網 sensor 先互相看（環距離＋路由父子偏置），再池化；
  - E04 的段間 attention（設計 B）顯著比串接好 → 候選之間保留一層 attention；
  - 不給候選編號 → 網路不能只靠「第幾段」偷懶（E04 瓶頸規則、E05 取最大都出現偏好單一段的崩塌）。
  - 「每回合可選的動作都不一樣」不會造成錯配：Q(s, c) 由候選自己的內容算出，TD 目標用下一回合 4 個候選的最大值
    （同 DRRN，He et al. 2016；隨機動作集合的 Q-learning，Boutilier et al. 2018）。
- 推論在 GPU 上（CPU 單執行緒一回合約 0.4 秒，太慢）。

### 5.1 獎勵／標籤（監督式和 RL 同一個定義）

**差異獎勵**：EN 更新時每個 searcher 只收 8 個 child1 中最好的、每個 good 一律換成 8 位拜訪者的 child2 中最好的，
所以一組交易的貢獻是「其他交易不變時，這組讓 searcher／good 的下一個值多了多少」：

- r1 = max(0, f(c1) − max(f(searcher), 同 searcher 其他 7 組 child1 的最好值))
- r2 = max(0, f(c2) − 同 good 其他 7 位拜訪者 child2 的最好值)
- reward = min((r1 + r2) ÷ scale, 5)；r1 + r2 ≤ 1e-12 → 0

例：S 的 8 組交易裡 child1 變好 +0.004、+0.003、+0.001，只有 +0.004 會被接受 → 三組分別得 0.001、0、0（舊的每組各算 Δ 會給三組都正獎勵）。
同一個 searcher 的 8 組都挑差不多的範圍時會自然被懲罰。

**尺度 scale**：上一回合「實際子代的一般 Δ」（max(0, f(c1) − f(S)) + max(0, f(c2) − f(G))）的正值中位數，行動前就已知；第一回合用本回合的。
- 原本 E04 用「本回合」的中位數，會受本回合所有交易的選擇影響。
- 原本提議的「每個 episode 固定尺度」實測不可行：E03 資料中正 Δ 中位數從第 1 回合到第 8 回合降 76 倍（3.8e-3 → 5.0e-5），
  固定尺度會讓後期獎勵幾乎是 0；而且各 episode 的第 1 回合中位數差 50 倍、衰減曲線差 10 倍以上，無法用固定曲線校正。

**監督式標籤**：作弊版在每組交易偷看 4 個候選「只交換、不突變」的結果（不計預算、不更新最佳），
標籤＝同樣的差異獎勵，其他交易固定為作弊版實際的選擇，scale 同上。**不含突變**（使用者 10/19 決定：突變的結果無法預測，標籤要乾淨）；
突變的平均影響留給 RL（RL 的獎勵來自實際子代，含突變）。
資料：`collect.py`，800 個 episode（8 shard），6,400 回合、409,600 組交易；標籤 > 0 的比例 7.1%。

### 5.2 監督式（`train_sup.py`）

Huber(Q_c, 標籤_c)，4 個候選都算（＝γ = 0 的 Q）；Adam lr 3e-4、L2 1e-5、batch 256、最多 40 epoch、驗證 Huber 6 次沒進步就停；
訓練圖依地圖切 10%（19 張圖）當驗證。

### 5.3 RL（`train_rl.py`）

- D3QN：Double DQN（γ > 0 時 1-step＋3-step，Huber）＋Dueling＋target network（每 1000 次更新）＋比例式 PER（α 0.4、β 0.6→1）。
  **γ = 0 是主設定**（目標就是 r；下一回合的 good 可能已被換掉、候選又重抽，加上差異獎勵後功勞大多在同一回合內分配完），γ = 0.5 是消融。
- 轉移：同一個 searcher、同一個 good 位置的下一回合；最後一回合終止。
- 800 個 episode；從零 ε 1.0 → 0.05、暖啟動 ε 0.2 → 0.05（前 50% episode 線性下降）；
  **每回合更新 16 次**（E04 是 4 次；共約 10 萬次更新），batch 128，lr 1e-4，L2 1e-5，梯度裁剪 10，warmup 5000 組。
- 超參數全部在 `config.json`。

### 5.4 訓練中驗證

20 份驗證快照（10 張驗證圖 × 快照 {1, 4}），同 seed 和隨機比單段最終 fitness，瓶頸規則同條件當參考（`results/data/val_baseline_20_1000.json`）。
RL 每 50 個 episode 驗證一次，`best.pt` 依對隨機的平均差選；監督式在訓練完用 best.pt 推進一次。
另記錄：每步改善率、4 段被選比例、每個 searcher 的 8 組交易用了幾個不同段（隨機約 3.6；檢查是否崩塌）。

## 9. 結論與下一步

1. **E06 監督式 +4.20%，拿到天花板 56%，顯著贏 E03 DeepSets（+1.28%），但和不學習的瓶頸規則打平**。
2. **全網前後文（sensor Transformer）沒有幫助**：0 層消融 lifetime、驗證指標都一樣。比 E03 DeepSets 好的部分來自其他改動
   （差異獎勵標籤、瓶頸分數特徵、候選間 attention 其中之一或組合），尚未拆開驗證。
3. **RL 沒有加分**：從零 +3.0%（顯著低於暖啟動）；暖啟動 ≈ 監督式；γ=0.5 沒有比 γ=0 好（−0.43%，ns）→ 沒有證據顯示選範圍需要考慮後續回合，
   目前這個問題表現得像 contextual bandit。RL 版本的最差場也比較差（663–732 對監督式 762、瓶頸規則 785）。
4. 資料量、地圖數不是瓶頸（30 張圖就和 169 張一樣）；和 E02／E03 一致，瓶頸是「4 選 1」的輸入資訊和動作空間本身。
5. 下一步候選（待討論）：行為複製版（分類）對照文獻做法；原版隨機推進、作弊版只標標籤（去掉分布偏移）；讓網路自己決定範圍（突破 4 選 1 天花板）。
